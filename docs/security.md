# 隐私与安全

这个工具处理的是**明文聊天数据**，请认真看：

- `workDir` 里会出现 `key.txt`（**明文密钥**）、`nt_msg.db`（约 1 GB 的解密副本）、`index.sqlite`（**全部消息的明文副本**）。用完建议整个删掉，把 `key.txt` 给别人等于把整个 QQ 数据库给别人。Linux 上 `workDir` 会自动设为 `0700`、`key.txt` 为 `0600`，但这不能替代用完即删；网页「设置 → 存储与清理」可以按类别删除这些文件。提取密钥时不会把密钥回显到终端或日志，只写入 `key.txt`。
- 设置文件只保存路径和端口，不含聊天内容或密钥；POSIX 上权限为 `0600`。设置页的写操作要求同源请求和自定义请求头，避免其他网页触发端口/目录修改或清理。
- 密码 ZIP 的密码通过 `QQNT_EXPORT_PASSWORD` 环境变量交给 Python 子进程，不出现在命令行参数里（`ps` 能看到参数，看不到别的进程的环境块），任务列表和日志也不保存它；Python 读取后立即从环境里删除。加密使用 AES-256（pyzipper），压缩包内的文件**名**仍然是明文。
- 导出目录和文件在 POSIX 上分别是 `0700` / `0600`，只允许写在 `workDir/exports` 内。CSV 里以 `=`、`+`、`-`、`@`、Tab、CR 开头的单元格会加前导单引号，避免 Excel / LibreOffice 把聊天内容当公式执行。 导出先写临时文件再原子改名，失败不会留下半截文件；Markdown 会转义 `|`、反斜杠和换行，HTML 会转义标签，SQLite 导出不会因群聊/私聊 `msg_id` 相同而丢消息。QQ 里没有时间戳的行（`ts=0`）在 TXT 里显示「未知时间」、CSV 留空、SQLite 保留原值，TXT/CSV/SQLite 行数一致；新版 `qqnt_export_chat` 按天拆分时归入「未知」文件。
- `key.json` 记录密钥属于哪个 QQ 账号；切换账号后建立索引或导出会直接提示重新提取，不会拿旧账号的密钥去试新库。
- 「默认源安装」/「清华镜像安装」会从 PyPI 或清华镜像下载 `sqlcipher3-wheels` 和 `pyzipper` 并安装到插件私有虚拟环境，需要网络；都不会修改系统 Python。镜像内容由清华镜像同步，若不可用可换默认源。uv 同样只写入该虚拟环境；它下载的托管 Python 落在 uv 自己的缓存目录（默认 `~/.local/share/uv/python`，可用 `UV_PYTHON_INSTALL_DIR` 覆盖）。
- 网页服务**只绑 `127.0.0.1`**，并拒绝非本机的 `Host` 和跨站 `POST`，但仍然建议只在本机使用。
- 设置页的「诊断」卡片与 `GET /api/diagnostics` 只回**元数据**：插件版本、系统与位数、解释器、`sqlcipher3`/`pyzipper` 是否可用、表结构指纹、消息数/会话数、上次构建的模式与原因。版本号本身不是隐私，写进卡片和诊断包是为了能一眼确认装的是哪一版（这次「重启后被 GitHub 版本覆盖」就是靠它发现的）。
- 侧边栏面板只经 `GET /api/qqnt/panel` 取地址与计数：插件版本、端口、是否在跑、索引条数、会话数、上次同步时间，**不含**消息、昵称、会话 id；页面本体走 iframe，聊天内容不进入 DSH 的 DOM。这个路由只接受本机 Host 与回环对端，DSH 被反向代理到局域网时返回 403。
- `workDir/presets.json` 只存导出选项（格式/脱敏/媒体/列），`workDir/export-tasks.json` 只存任务 id、状态、条数、时间与文件名（不存绝对路径），单会话导出的任务名落盘时写成「聊天记录」而不是会话名。
- **诊断包**（设置 → 诊断 → 下载诊断包，`GET /api/diagnostics/bundle`）是白名单拼出来的，只含这些字段：
  - `version`（插件版本）、`generatedAt`（生成时间，ISO）；
  - `platform`：`os` / `arch` / `bits` / `python` 版本号、`sqlcipher3` 与 `pyzipper` 是否可用、QQ 进程数、内存读取方式、是否找到数据根、账号个数、**账号的 `sha1` 前 8 位**；
  - `paths`：数据根、`nt_db`、`nt_data`、工作目录、解释器、索引、虚拟环境的**最后一段**（例如 `Tencent Files`、`work`、`python.exe`）；
  - `schema`：表结构指纹、缺失列（只有列号，不含数据）、表数量；
  - `index` / `build` / `sync`：索引版本与指纹、消息数、会话数、搜索模式、上次构建的模式与耗时、**全量重建的原因**（`fullReason`，如源库删过消息）、是否 WAL 待合并、表结构是否变化、是否自动同步与间隔；
  - `deps`：`sqlcipher3` / `pyzipper` / uv 版本，以及探测失败的原因（已把路径与账号替换掉）；
  - `storage`：解密副本、索引、临时导出的**字节数**；`errors`：最近一次构建/同步的错误（截断到 300 字并脱敏）。
  它**不含**消息正文、昵称、群名、会话 id、`key.txt` 内容，也不含任何 QQ 号明文；贴 issue 前可以自己打开看一眼，确认没有想保密的内容再上传。
- 对所有 QQ 数据**只读**：不修改 Windows 的 `Documents\Tencent Files` 或 Linux 的 `~/.config/QQ` 下任何文件，不结束 QQ 进程。
- 媒体文件**默认不复制**：`[图片]` `[视频]` `[语音]` `[文件]` 在普通导出里只是占位符，原文件仍在 `nt_qq\nt_data\`（Windows）或 `nt_qq_<hash>/nt_data/`（Linux）。勾选「含媒体」或 `--media` 时才会把本机已下载的文件复制进 ZIP；导出过程只读 `nt_data`，不修改、不移动任何原文件。
- Linux 上为了读内存而放开 `ptrace_scope` 会降低本机进程间的隔离性，导出完成后请改回默认值。
- 脱敏只作用于结构化字段（发送者、QQ 号、会话名、清单），**不会改写正文**；正文里被引用的昵称、手机号仍会保留，分享前请自行检查。
- 一次批量导出最多 200 个会话；媒体导出需要先建好索引（用的是构建时复制的 `nt_msg.db`），并且必须指定会话。
- 只应导出你自己有权访问的记录。
