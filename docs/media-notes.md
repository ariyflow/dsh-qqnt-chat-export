# 媒体导出：实测结论（2026-10-29）

导出媒体（图片/文件/语音/视频）前先做了一次真机 spike：读 `nt_msg.db` 里
`40800` 消息段，确认每类媒体在 `nt_data` 下的落盘规则。样本是 32 万条、
140 个会话的账号（单账号）。

## 1. 每种媒体在哪

| 类型 | 消息段字段 | 本机路径规则 | 备注 |
|---|---|---|---|
| 图片 | `45002=2` | `Pic/<yyyy-mm>/Ori/<md5>.<ext>` | `45812` 直接给出绝对路径；`45406` 是 16 字节 md5 |
| 缩略图 | 同上 | `Pic/<yyyy-mm>/Thumb/<md5>_<spec>.<ext>` | 原图没下载时退回缩略图，并在清单里标记 `thumbnail` |
| 表情 | `45002=2`，路径在 `Emoji/` 下 | `Emoji/emoji-recv/<yyyy-mm>/Ori/<md5>.0` | 数量多、体积大（本机 1.2 GB），默认跳过 |
| 语音 | `45002=4` | `Ptt/<yyyy-mm>/Ori/<md5>.amr` | `45402` 是 `<md5>.amr`；不做转写 |
| 视频 | `45002=5` | `Video/<yyyy-mm>/Ori/<md5>.mp4` | 很多会话只有 `Thumb/<md5>_0.png`，按缩略图导出 |
| 文件 | `45002=3` | `File/Ori/<前缀>_<uuid>/<原文件名>` | uuid 来自 `45503`（形如 `/3c6e2418-…`）；未下载的传输没有本地文件 |

`45812` 只在图片元素上出现，且是**绝对路径**（换机器/清理缓存后会失效），
所以查找顺序是：`45812` → 按 md5 在 `Ori` 里找 → 按 md5 在 `Thumb` 里找。
文件传输没有本地路径字段，只能按 `45503` 的 uuid 找目录。

本机覆盖情况（只统计已落盘）：

| 目录 | 文件数 | 说明 |
|---|---|---|
| `Pic/**/Ori` | 1,987 | 大部分图片只保留发生在近期会话里的 |
| `Ptt/**/Ori` | 147 | 语音缓存很干净，旧消息基本没有 |
| `Video/**/Ori` | 部分 | 视频通常不自动下载 |
| `File/Ori` | 3 | 只有用户点过"下载"的传输 |

结论：媒体导出必须**默认关闭**、按会话导出、缺失文件只记录不报错。

## 2. 实现

- `scripts/qqnt_media.py`：解析 `40800` 段的 `45002/45402/45405/45406/45503/45812`，
  按上面的规则定位；`collect()` 先用索引里的 `seg_kinds` 筛出媒体消息，再读
  构建时复制的 `work/nt_msg.db`（源库始终只读）。
- 导出格式：`--media` 必然产出 ZIP（每个会话一个文件 + `media/<会话>/…` +
  `manifest.json`）；清单里记录 `files / bytes / missing / skipped / missingCount`。
- 上限：单文件 100 MB、单次 1 GB；超过的写入 `skipped`（`too-large`、
  `total-limit`），不会让导出失败。
- 脱敏：`--redact names|qq|all` 时媒体文件名改成 `图片-<msgId>-<序号>`，
  不复用原始文件名（文件名里可能带真名）。
- `--embed-media`：只支持 HTML、单个会话；图片转 base64 data URI 内嵌，
  单文件 10 MB、单次 200 MB；非图片媒体跳过并计入 `skipped`。

## 3. 已知限制

- 只导出**本机已经下载**的媒体；QQ 过期清理、换机、卸载重装都会让旧媒体缺失。
- 语音是 `.amr` 原文件，不转码、不转写；`Ptt` 目录被清空时只剩占位符。
- 媒体路径是绝对路径，QQ 数据目录移动后按 md5 回退仍能找到，但仅限同一份缓存。
- 表情（`Emoji/`）不导出；如果确实需要，可再开一个开关，但要先解决体积问题。
